# 안전보건관리체계 이행 관리 시스템 (SHMS)

> 아성다이소 안전보건팀 · **중대재해처벌법 · 산업안전보건법 이행관리 및 ISO 45001:2018 심사 대응 시스템**

---

## 1. 이 시스템은 무엇을 하는가

| 목적 | 시스템에서 하는 일 |
|---|---|
| **중대재해처벌법 대응** | 시행령 제4조(9개 호)·제5조(4개 호) 의무별 이행 현황을 조항 단위로 작성·관리 |
| **산업안전보건법 대응** | 유통·물류업 적용 주요 의무조항 19개의 준수 여부 점검 |
| **ISO 45001 심사 통과** | 4~10장 요구사항 30개를 조항 ↔ 문서 ↔ 증빙으로 매핑한 **심사 대응 매트릭스** 제공 |
| **문서체계 구축** | 매뉴얼 → 절차서 → 지침서 → 양식 4단계 46개 문서를 앱 안에서 직접 작성·개정이력 관리 |
| **이행 증빙 확보** | 반기 점검 기록, 개선조치(CAPA), 증빙 자료함, 법정 선임 현황을 하나로 연결 |

**총 62개 법령·표준 조항 + 46개 문서**가 기본 탑재되어 있으며, 각 항목은 **모두 수기로 직접 작성**할 수 있습니다.

## 2. 기술 구성

```
GitHub Pages (정적 호스팅)  ←  index.html + css + js  (빌드 도구 없음, 순수 ES Module)
        │
        └─▶ Supabase (PostgreSQL + Auth + RLS)   ← 운영 데이터 저장소
                    │
                    └─▶ localStorage 캐시         ← 오프라인·폴백 저장
```

- **빌드 과정이 없습니다.** 파일을 그대로 올리면 동작합니다.
- **Supabase 미설정 상태에서도 즉시 사용 가능**합니다 (로컬 저장 모드).
- Supabase 연결 후에는 **전사 공유 + 로컬 캐시 이중 보관**으로 동작합니다.

## 3. 처음 시작하기

### 3-1. 로컬에서 바로 열어보기

```bash
python -m http.server 8899
```

브라우저에서 `http://localhost:8899` 접속 → 아무 이메일로 로그인.

> ⚠️ `index.html`을 파일로 직접 더블클릭하면 **동작하지 않습니다.** ES Module은 http 주소에서만 로드됩니다. 반드시 위 명령으로 서버를 띄우거나 GitHub Pages에 배포해서 사용하세요.

### 3-2. Supabase 연결

1. [supabase.com](https://supabase.com) → New project 생성
2. 대시보드 → **SQL Editor** → `supabase/schema.sql` 전체 붙여넣기 → Run
3. **Authentication → Users → Add user**로 계정 생성 (예: safeteam119@gmail.com)
4. SQL Editor에서 관리자 권한 부여

   ```sql
   update public.shms_profiles
      set role = 'master', name = '안전보건팀 관리자', dept = '안전보건팀'
    where email = 'safeteam119@gmail.com';
   ```
5. 앱 로그인 → **[설정 · 백업]** 화면에서 **Project URL**과 **anon public key** 입력 → 저장

   > Project URL / anon key 위치: Supabase 대시보드 → Project Settings → API
   > **service_role 키는 절대 입력하지 마십시오.** 앱이 거부합니다.

### 3-3. GitHub 배포

```bash
git remote add origin https://github.com/<계정>/<저장소>.git
git branch -M main
git push -u origin main
```

저장소 → **Settings → Pages → Source = GitHub Actions** 로 설정하면 push할 때마다 자동 배포됩니다.

Supabase 키를 저장소에 두고 싶지 않으면 **Settings → Secrets and variables → Actions** 에
`SUPABASE_URL`, `SUPABASE_ANON_KEY` 를 등록하세요. 배포 시 `config.js`가 자동 생성됩니다.

## 5. 권한 체계

| role | 화면 표기 | 권한 |
|---|---|---|
| `master` | 시스템 관리자 | 작성·수정 |
| `safety` | 안전보건팀 | 작성·수정 |
| `head` | 안전보건팀장 | 작성·수정 |
| `auditor` | 심사원/감사 | 읽기 전용 |
| `part` / `store` / `ref` | 파트장 / 점장 / 참조 | 읽기 전용 |

권한은 Supabase `shms_profiles.role` 값으로 결정되며, RLS 정책이 **서버에서** 강제합니다.
앱 화면의 버튼 비활성화는 편의 기능일 뿐이며 실제 통제는 RLS가 수행합니다.

## 6. 백업 원칙 (안전보건팀 작업규칙)

1. Supabase가 운영 원본이지만, **D드라이브 백업을 반드시 병행**합니다.
2. [설정 · 백업] → **전체 백업 내려받기**로 주기적으로 JSON을 저장하세요.
3. 파일명 규칙: `안전보건관리체계_이행관리_백업_claude_{년도}_{월일}.json`
4. 심사 직전에는 반드시 백업을 한 번 더 받아 두십시오.

## 8. 주의사항

- `js/data/frameworks.js`의 조문은 **실무 요약본**입니다. 최종 법적 판단은
  [국가법령정보센터](https://www.law.go.kr) 원문을 기준으로 확인하십시오.
- 법령 개정 시 `frameworks.js`를 갱신해야 합니다 (ISO 6.1.3 / 중처법 시행령 제5조 1호 의무).
- 개인정보(근로자 성명·건강정보 등)를 이 시스템에 대량 저장하지 마십시오.
  증빙 자료함에는 **자료의 위치**만 기록하고 실물은 사내 문서고에 보관합니다.
