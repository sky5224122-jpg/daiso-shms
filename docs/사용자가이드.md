# 사용자 가이드 — 안전보건관리체계 이행 관리 시스템

> 대상: 안전보건팀 담당자 · 안전보건팀장 · ISO 45001 심사 대응 담당자

---

## 1. 이 시스템을 쓰는 순서 (권장 작업 흐름)

```
① 조직·법정선임 등록  →  ② 문서체계 작성  →  ③ 조항별 이행현황 작성
        ↓                                              ↓
④ 증빙 자료함 등록  ←───────────────  ⑤ 반기 이행점검 실시·기록
        ↓
⑥ 미흡사항 → 개선조치(CAPA) 등록 → 종결
        ↓
⑦ 심사 대응 매트릭스 인쇄 → ISO 45001 심사 대응
```

---

## 2. 화면별 작성 요령

### 2-1. 조항별 이행현황 작성 (핵심)

**[중대재해처벌법] / [산업안전보건법] / [ISO 45001 요구사항]** 화면에서
조항 카드를 클릭하면 오른쪽에 작성 패널이 열립니다.

패널 상단에는 **조문 요지 · 이행해야 할 내용 · 권장 증빙자료**가 미리 정리되어 있으니
읽고 나서 아래 3개 항목을 작성합니다.

| 항목 | 작성 요령 | 나쁜 예 | 좋은 예 |
|---|---|---|---|
| **① 이행 현황** | 날짜·주체·수량을 반드시 포함 | "방침을 수립함" | "2026.07.15 대표이사 명의 안전보건 경영방침 제정, 전 매장 376개소 게시 완료" |
| **② 보유 증빙자료** | 문서명 + 보관 위치를 함께 | "관련 서류 있음" | "1. 방침 선언문(대표이사 서명본) — 안전보건팀 문서고 3번 캐비닛" |
| **③ 미흡사항** | 없으면 '해당없음'이라고 명시 | (공란) | "2개 매장 게시 누락 확인 → CAPA-2026-014로 등록" |

> **심사원은 "했다"는 말이 아니라 "언제·누가·무엇을 근거로 했는지"를 봅니다.**
> ①에 날짜와 수량이 없으면 관찰사항이 될 가능성이 높습니다.

**이행 상태**는 다음 기준으로 선택합니다.

| 상태 | 선택 기준 |
|---|---|
| 이행완료 | 절차가 있고, 실행했으며, 증빙이 있다 |
| 이행중 | 절차는 있으나 실행·증빙이 일부만 있다 |
| 보완필요 | 실행했으나 미흡사항이 확인되었다 |
| 미이행 | 절차나 실행 중 하나라도 없다 |
| 해당없음 | 사업장 특성상 적용되지 않는다 (사유를 ①에 반드시 기재) |

> ⚠️ **해당없음**을 선택할 때는 반드시 판단 근거를 ①에 쓰십시오.
> 근거 없는 '해당없음'은 심사에서 가장 흔한 지적 사유입니다.

### 2-2. 반기 전환

상단 우측의 **반기 선택**(예: `2026년 하반기`)을 바꾸면 그 반기의 기록이 표시됩니다.
**이전 반기 기록은 지워지지 않고 그대로 보존**되며, 이것이 "반기 1회 이상 점검"의 이력 증빙이 됩니다.

새 반기가 시작되면 상태가 초기화된 것처럼 보이는 것이 정상입니다. 그 반기에 대해 다시 점검·작성하십시오.

### 2-3. 문서체계 (절차서·지침서)

문서를 클릭 → **목적 · 적용범위 · 본문**을 작성합니다.
**[📋 표준 목차 불러오기]** 버튼을 누르면 아래 목차가 자동 입력됩니다.

```
1.목적 → 2.적용범위 → 3.용어의정의 → 4.책임과권한
→ 5.업무절차 → 6.관련법규 → 7.관련문서및양식 → 8.기록의보존
```

문서 상태를 **제정/승인**으로 바꾸면 문서체계 구축률에 반영됩니다.
개정할 때는 하단 **제·개정 이력**에 차수·일자·변경내용을 추가하십시오.
**ISO 45001 7.5(문서화된 정보) 심사에서 개정이력은 반드시 확인되는 항목입니다.**

### 2-4. 이행 점검

중처법 시행령 제4조 3·5·7·8·9호와 제5조는 **반기 1회 이상 점검 의무**가 있습니다.
점검을 실시했으면 **[＋ 점검 실시 기록 등록]**으로 다음을 남기십시오.

- 점검일 / 점검자 / 점검 구분
- 점검 대상·범위 (예: 전국 직영매장 376개소)
- 점검 방법 (예: 현장 방문점검 + 앱 제출자료 검증)
- 점검 결과 / 지적·미흡 사항 / 필요한 조치

> 점검을 했더라도 **기록이 없으면 하지 않은 것으로 판단**될 수 있습니다.

### 2-5. 개선조치 (CAPA)

점검·심사·사고에서 나온 미흡사항은 여기에 등록해 종결까지 추적합니다.

**근본원인 분석**란에는 표면 원인이 아니라 **왜 그런 상태가 되었는가**를 씁니다.

- 표면 원인: "점검표를 작성하지 않았다"
- 근본 원인: "점검표 양식이 매장에 배포되지 않았고, 관리감독자 교육에 점검표 작성 항목이 없었다"

**시정조치**는 관리 위계(제거 → 대체 → 공학적 → 행정적 → 개인보호구) 순으로 검토합니다.

### 2-6. 심사 대응 매트릭스

ISO 45001 심사 직전에 **[🖨️ 심사 대응 팩 인쇄]**를 누르면
조항 ↔ 대응문서 ↔ 이행현황 ↔ 관련법령이 한 표로 정리되어 출력됩니다.

**"미작성 — 심사 지적 위험"** 이라고 빨갛게 표시된 행이 있으면
심사 전에 반드시 채워 넣으십시오.

## 3. 심사 전 최종 점검 체크리스트

- [ ] 종합 이행률이 80% 이상인가
- [ ] "중대 미이행·보완" 건수가 0인가
- [ ] 심사 대응 매트릭스에 "미작성" 행이 없는가
- [ ] 문서체계 구축률이 100%이며, 모든 절차서에 제정일·승인자·개정이력이 있는가
- [ ] 반기 점검 실시 기록이 등록되어 있는가
- [ ] 진행중 CAPA에 완료 기한이 지난 건이 없는가
- [ ] 법정 선임자 전원의 선임일·직무교육·반기평가가 기록되어 있는가
- [ ] **[설정 · 백업]에서 전체 백업 JSON을 내려받아 D드라이브에 보관했는가**

## 4. 자주 묻는 질문

**Q. 화면이 안 뜹니다.**
A. `index.html`을 파일로 직접 열면 동작하지 않습니다. `python -m http.server 8899` 로 서버를 띄우거나 배포된 웹 주소로 접속하십시오.

**Q. 작성한 내용이 다른 PC에서 안 보입니다.**
A. Supabase가 연결되지 않은 로컬 모드입니다. 우측 상단에 "🟡 로컬 저장"으로 표시됩니다. [설정 · 백업] 화면에서 Supabase를 연결하면 전사 공유됩니다.

**Q. 저장했는데 "동기화 실패"라고 나옵니다.**
A. 로컬에는 저장되었지만 Supabase 전송에 실패한 상태입니다. 네트워크 또는 권한(RLS)을 확인하고, 연결 복구 후 해당 항목을 다시 저장하십시오.

**Q. 버튼이 눌리지 않고 "읽기 전용"이라고 나옵니다.**
A. 계정 권한이 읽기 전용(심사원·파트장·점장·참조)입니다. 작성 권한은 `master` / `safety` / `head` 입니다.

**Q. 법이 개정되면 어떻게 하나요?**
A. `js/data/frameworks.js`의 해당 조항을 수정합니다. **`id` 값은 절대 바꾸지 마십시오** — 기존 이행기록과의 연결이 끊어집니다.
